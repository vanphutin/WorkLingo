## Bind the application before exposure

The facilitator must obtain the exact approved application origin, published lessonVersionId, newly created sessionId and activity IDs with the corresponding authored slug/type. Capture a sanitized observed manifest independently from the actual displayed/session API state. Do not copy expected IDs into observed fields. Neither manifest may contain answers, tokens, cookies, names, email or arbitrary metadata.

Call the exported pure `validateApplicationBinding(kitLesson, approvedBinding, observedBinding)` before starting exposure. The approved shape is lesson, sourceSha256, bundleSha256, audioSha256, origin, lessonVersionId, sessionId and ordered activities `{slug,activityType,id}`. Observed has those same fields plus launchUrl. UUIDs must be actual supplied IDs; none are generated by the kit. HTTPS is required except HTTP loopback. Launch URL must exactly equal `origin + /sessions/ + sessionId`, without query, fragment or credentials. Reject mismatched sessions, published versions, source/bundle/audio, ordered activity mappings and duplicate activity IDs.

Success means STRUCTURE_MATCH_ONLY, humanEvidence=false, studyAuthorityVerified=false. It is not authentication, browser automation, independent observation or permission to start a study. This library does not contact the application, operate the browser, create sessions or answer tasks. Current real execution remains NOT_RUN; approved operator integration must collect the actual manifests.

Use exported `bindSessionEvidence(kitLesson, approvedBinding, observedBinding, facilitatorSession)` to produce a private sidecar after structural validation. It binds the application's session/version/activity identity to the facilitator exposure's pseudonymous slot, lesson, startedAt and bundle/audio. A different lesson or audio is rejected. Keep that sidecar with its matching private STARTED/completed records under the separately approved storage contract; it contains session identifiers and individual exposure start and must not enter the public aggregate export or Git. The sidecar excludes outcomes/answers and still reports humanEvidence=false: matching supplied structures cannot authenticate a person, consent or observations. This pure function writes no files and does not bypass the study-gated CLI.
