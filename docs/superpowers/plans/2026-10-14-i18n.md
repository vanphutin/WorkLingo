# WorkLingo i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for foundation/integration; use dispatching-parallel-agents for disjoint API and UI slices. Steps use checkbox syntax for tracking.

**Goal:** Deliver complete Vietnamese / English system UI with state-preserving switching and account persistence.
**Architecture:** next-intl ICU translation functions behind shared typed hooks; feature namespace catalogs, cookie/authenticated SSR resolution, and validated preference APIs. Existing routes and education data remain intact.
**Tech Stack:** Next.js 16.3.8, React 19, NestJS 11, Prisma 6, Zod 4, next-intl, Vitest, Playwright.
**Spec:** `docs/superpowers/specs/2026-10-14-i18n-design.md`

## Global Constraints

- `vi`: Tiếng Việt — mặc định cho người dùng mới; `en`: English.
- Không phá các URL hiện tại như `/dashboard`, `/programs`, `/login`, `/admin/...`.
- Không reset learning sessions. Không thay đổi dữ liệu học tập đang published.
- Không xóa hoặc ghi đè các thay đổi chưa commit của người dùng.
- Không tự động push/merge khi chưa được yêu cầu.
- No database migration; no stacked i18n libraries; no runtime AI translation.

## Review Focus

1. An old locale save response arrives after switching accounts: it must not alter the new account or UI.
2. Browser storage is unavailable: switching/cookie persistence must remain usable.
3. API unavailable during SSR: use a validated cookie without caching another user's preference.
4. Locale changes during writing/recording: preserve draft, component identity, audio and attempt identifiers.
5. Dynamic enum/error/date strings: localize display without changing machine identifiers or timestamps.
