## Architecture and decisions

Extend TeacherAiModule, EvaluationService and LanguageEvaluationPort. Add an optional structured assessment operation to existing language adapters, a shared strict result contract, skill-specific rubric/evaluator policies and a context resolver using the exact session lesson snapshot and enrollment program version. Objective comprehension retains deterministic answer verification; all semantic decisions use primary AI and independent verification. No regex/string-match semantic grader and no second submission/curriculum system.

Add EvaluationRun as append-only history owned by ActivityAttempt, leaving EvaluationResult and its legacy unique key intact. A run contains exact identities/hashes, rubric/policy/prompt versions, role-specific actual model metadata, criteria/evidence, terminal status, nullable score, timestamps and previous-run reference. Idempotency is per attempt/request key; a new re-evaluation appends a linked run. A short transaction/advisory lock serializes admission; provider work occurs outside the transaction with a bounded timeout and a recoverable expired lease. Terminal rows are immutable through a database trigger. Learner history is owner-scoped and returns a whitelist; admins inspect audit context and initiate re-evaluation under existing role/rate-limit rules. No new override permissions.

Four evaluators share 0–3 required weighted criterion levels. Primary and verifier score independently without seeing one another's result; disagreement produces NEEDS_REVIEW unless a separately configured adjudicator resolves it. Same-model verification is recorded as correlated evidence, never independent model-family proof. Missing evidence, invalid schemas, confidence uncertainty and cancellation cannot become numerical success. Mandatory acoustic criteria require real provider acoustic evidence with audio checksum/timing; transcript-only speaking cannot produce a total. Objective question keys are checked by deterministic code, including typed accepted answers only when explicitly authored.

Speaking reuses secure recording storage, consent, transcription and Microsoft Speech adapter. Validate WAV properties/checksum and voice energy before processing supported PCM; preserve words/phonemes/syllables and optional prosody without inventing dimensions. Unsupported formats require existing actual decoder/provider capability or fail explicitly. A synthetic tone is audio-validation evidence, not pronunciation qualification. Deleted audio cannot be processed/reused.

Scored assessment history projects separate four-skill evidence summaries (observation count, recency, consistency, confidence, gaps and suggested review) without mutating completion or claiming CEFR certification. Re-evaluations of one submission count once. Fake providers are explicitly synthetic and cannot qualify a skill. Qualified-policy activation is a separate gate, default disabled; all four skills can request an assessment of their persisted learner submission through existing Teacher AI routes. R2.1's participation flow remains intact until a qualified policy is explicitly activated.

## Privacy, reliability and provider boundary

Private passage/transcript/keys/rubrics stay server-side. Prompt uses bounded JSON data, never interpolated instructions. Structured outputs require evidence references and exact criterion sets; aggregator rejects missing/duplicate/unknown criteria and invalid spans/timestamps. Learner evidence quotes must be submission-derived; private source evidence is not projected. Provider metadata unknowns remain null. No chain-of-thought requested/stored. Store:false and verified provider policies are necessary but do not imply zero retention. Provider/privacy/budget not established means sensitive/live requests remain disabled. No credit purchase/top-up/limit increase.

Default verification uses synthetic data, local HTTP provider fixtures through real serializers and an isolated disposable PostgreSQL instance. Real-provider calibration requires confirmed authorization/quota/privacy; unavailable calibration is BLOCKED, not AI_QUALIFIED. Benchmarks separate authored keys, source-backed references, synthetic adjudication and human references, preserve historical failures, report denominators and confidence intervals. Proposed mission thresholds stay unchanged. Human validation is NOT_RUN.

## Acceptance

All four skills have actual attempt-backed assessment request/history and feedback UI; exact snapshot context, retry/idempotency/re-evaluation/cancellation and redaction are tested. Additive migration/immutability/rollback are exercised on disposable DB. Browser covers Next/Nest/Postgres, four skills and responsive/error states. Full relevant regressions, fresh independent review, scoped commits and final remote SHA receipt are required before main integration. Engineering, TESTED/VERIFIED, AI_QUALIFIED and HUMAN_VALIDATED are distinct. No production deployment without independently verified target/config/backup/health/rollback.
