# Vietnamese / English UI internationalization

Authority: the user's attached implementation mandate, 2026-10-14. Autonomous implementation is explicitly approved; no push, merge or publication is authorized.

## Decisions

- Preserve the current dirty checkout on `codex/ui-redesign-v2`, including the pending redesign and verification fixes. Record a baseline before editing; do not commit mixed user changes.
- Keep every URL unchanged. Use next-intl's ICU translator with a shared locale context and feature-owned namespace dictionaries. Components import only their feature dictionaries; the root does not serialize an entire application catalog. Both supported languages can be present in a feature chunk to allow synchronous switching without unmounting children.
- Official UI locales: `vi` (default), `en`. Speech remains `en-US` where currently specified. Locale formatting uses Intl with explicit timezone only when available; changing locale never changes an instant.
- SSR resolves an authenticated account's stored preference before the guest cookie. API unavailable: use the validated UI cookie, then Vietnamese. Only forward the session cookie to the configured internal API; disable caching.
- Current explicit switch wins within the mounted UI. Persist authenticated switches through validated `GET/PATCH /me/preferences`; server preference wins at login and reload. Guest switches use a SameSite=Lax, path=/ cookie. Registration may explicitly carry the guest locale; existing clients still default to vi.
- Reuse LearnerProfile.locale. For admins without a profile, lazily create an otherwise default profile on explicit preference update; this creates no enrollment, progression or learning session. Role authorization continues to determine access.
- Synchronize tabs with scoped browser events, never write a received account event back to the server. Ignore another account's events. Re-read on tab focus to pick up changes from other devices. Logout preserves the last display locale as the guest cookie, but the next login always adopts the next account's server preference.
- Translate system UI, authored system status labels, validation and stable API error code mappings. Preserve curriculum prose, lesson passages, transcripts, vocabulary, answers, user names and user-created content. English practice passages receive lang=en semantics.
- Shared native select with visible language names, localized accessible label, keyboard support and existing design tokens. Reuse in auth/public, learner, admin and settings.

## Acceptance

Unit: locale validation, defaults, precedence, ICU interpolation/plurals, fallback, formatting, state preservation and persistence failures. Integration: authenticated read/update, invalid input, ownership, learner/admin and unchanged legacy contracts. E2E: guest switch/reload, login/account precedence, navigation, settings/session state, logout/relogin, tabs, admin, keyboard/mobile, SSR lang and no hydration errors. Catalog tooling checks paired keys, ICU placeholders, used/missing keys and inventories excluded learning/technical content. Run the existing full `pnpm verify` gate and report actual results.

## Future content localization

Any curriculum localization should live in separately reviewed locale variants keyed by immutable lesson version and field, with provenance and publication validation. This implementation does not migrate or translate published learning content.
